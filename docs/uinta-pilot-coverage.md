# Uinta pilot point: source coverage and evidence limits

Audit target: longitude **-109.99532020981788**, latitude **40.31458853576911** (WGS 84; EPSG:4326). This is a point-level audit plan and source inventory, not a claim that every source returned a record at that coordinate.

## What was and was not verified

Authoritative service documentation and the repository's current API adapters were inspected on 2026-09-22. The initial audit could not make point-specific requests because its sandbox blocked outbound HTTPS. The table records that initial source inventory. A later local runtime check with network access verified soil, geology, and Utah well responses at the pilot point; its findings below supersede those three "not queried" entries. Elevation source resolution, vertical datum, imagery acquisition date, and Skyline 16 coordinates remain unverified.

## Live pilot follow-up, 2026-09-22

With the local preview running and public network access enabled, the exact pilot point returned:

- **SSURGO:** map unit 243, “Turzo-Umbo complex, 0 to 2 percent slopes,” with Turzo as the dominant published component (65%). The response supplied three representative horizons, 1% component slope, and surface pH 8.5. These are map-unit/component values, not a test on the selected pad.
- **Macrostrat:** several overlapping mapped units. The initial displayed unit was “Eocene-Oligocene sedimentary”; the app retained the original map source reference. The overlapping units are alternative survey interpretations, not stacked underground layers.
- **Utah wells:** the app returned 12 distance-sorted records within 15 km. The source's separate count query returned 1,874 non-confidential records in that circle, below its 2,000-record transfer cap. The closest displayed records included public “Producing” Powell well entries at or near the pilot pad. Status and operator names are the agency's published attributes and should be rechecked at the source.
- **Terrain and imagery:** MapLibre rendered the terrain and imagery in the browser. One USGS NAIP Plus tile request failed transiently in that session while Esri imagery remained visible. No exact underlying aerial scene/date, active DEM posting, or vertical datum was identified, so no local resolution claim follows from this visual check.

The Skyline 16 core remains a separate regional reference. Its coordinates are still intentionally absent from the map and its depth interval is not correlated with the Powell well records.

## Elevation: resolution and datum rules

Keep the following distinctions in any implementation or user-facing report:

- **Tile metadata is not local ground resolution.** Mapterhorn's 512-pixel tiles describe encoding and image dimensions. Ground spacing changes with zoom and latitude; source DEM posting can be coarser than the rendered tile pixels. A displayed 1 m pixel is not evidence of 1 m measurements.
- **A composite is not a single survey.** Mapterhorn's public attribution page points to a contributor list. The source active under this point must be established from its coverage metadata before naming an upstream DEM, date, resolution, or license.
- **3DEP is a separate check.** EPQS should be queried independently; retain the returned elevation units, horizontal location, source/resolution metadata, and vertical datum. USGS documents NAVD88 as typical, not universal.
- **Do not mix vertical datums silently.** Mapterhorn's tile metadata must be checked for elevation reference. A USGS NAVD88 elevation and a tile value with unknown or different vertical datum are not directly comparable without a documented transformation. Horizontal WGS 84 coordinates do not define a vertical datum.

## Live dependency behavior in this repository

Current app routes are live proxies, not a cached pilot evidence snapshot:

- `/api/soil` calls USDA NRCS Soil Data Access / SSURGO and returns HTTP 502 with `USDA soil survey service unavailable` when the upstream request fails.
- `/api/geology` calls Macrostrat `geologic_units/map` and returns HTTP 502 with `Geology service unavailable` on upstream failure.
- `/api/wells` calls the UGRC ArcGIS feature service and returns HTTP 502 with `Utah well data service unavailable` on failure.
- Terrain and NAIP are requested by the client from tile/image services; a static 200 from the app does not prove those third-party layers loaded.

During the initial source inventory, the audit environment denied outbound sockets. The later local runtime check used public network access and returned point-specific soil, geology, and well data as described above. The app should preserve the difference among not queried, no mapped record, partial/limited data, and upstream unavailable; it should never turn a timeout into a “no data” finding.
